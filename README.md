# TalentFlow ATS: Applicant Tracking System on AWS (Floci)

Team 29 · Cloud Computing & Cloud Security (26CSCN29H) · Final phase

Recruiters post jobs and move candidates through hiring stages with interview scorecards.
Candidates apply with their CV and follow their progress. The system reports
**time-to-hire, candidates per stage and source of applicants**.

![Architecture](docs/architecture.svg)

## Services and owners

| Service | Owner | Lambda | AWS services used by this component | Main functions |
|---|---|---|---|---|
| Job Management + Hiring Analytics (+ shared auth) | **Marwan** | `ats-jobs-service` | Lambda, API Gateway, DynamoDB (`AtsUsers`), Secrets Manager, CloudWatch (+ Neon Postgres) | register/login/staff accounts, create/edit jobs, publish/unpublish/close workflow, search jobs, departments, analytics dashboard + snapshots |
| Candidates & Applications | **Laila** | `ats-candidates-service` | Lambda, DynamoDB (`AtsCandidates`, `AtsApplications`), S3 (private CV bucket), SQS | candidate profile, CV upload/replace/download, apply (business rules), my applications, withdraw, applicant search |
| Recruitment Pipeline + Notifications | **May** | `ats-pipeline-service`, `ats-notifier` | Lambda ×2, DynamoDB (history, reviews, interviews, notifications), SNS, Secrets Manager, **Brevo email API (external)** | stage state machine, scorecards, interview scheduling with clash detection, kanban board, audit history, candidate emails |

How the services talk to each other: each service is its own Lambda with its own tables and IAM role.
They call each other **Lambda-to-Lambda** on `/api/internal/*` routes. These routes are not exposed
through API Gateway, and each call needs IAM permission plus a 60-second service token. Emails are
sent **asynchronously** through SNS and SQS, so a slow email provider never slows down a user action.

| Caller → callee | Why |
|---|---|
| candidates → jobs | is the job published and still open before accepting an application? who is the hiring manager? |
| jobs → candidates | can this job be unpublished (does it have applications)? analytics data |
| jobs → pipeline | analytics: stage funnel and days per stage |
| pipeline → candidates | load an application, move its stage (optimistic lock) |
| pipeline → jobs | count a hire (auto-closes a filled job), check an interviewer |
| candidates → pipeline | a withdrawal is written to the audit trail and cancels upcoming interviews |

## Run it on Floci (local AWS)

Needs Docker Desktop, Node.js 22+, Git Bash and AWS CLI v2.

```bash
bash infra/setup-floci.sh      # starts Floci + Postgres, creates EVERYTHING, prints the URLs
node scripts/seed.js           # demo accounts + demo data (passwords -> infra/demo-accounts.local.json)
```

- Website: <http://localhost:4566/ats-web-local/index.html>
- Floci console: <http://localhost:4566/_floci/ui>
- Re-deploy one member's service only: `bash infra/services/20-candidates.sh` (etc.)

## Tests and evidence

```bash
node --test --test-concurrency=1 "tests/*.test.mjs"    # 22 integration + 18 security tests against the deployed API
bash infra/monitoring-report.sh             # CloudWatch metrics, alarms, log filters -> evidence/monitoring.md
k6 run -e API_URL=<api-url> tests/k6/load-test.js   # load test (Lab 8 tool)
```

Results are written to `evidence/` (integration-tests.md, security-tests.md, monitoring.md, load-test.md).

## Secrets (none in this repository)

- Real values live only in **AWS Secrets Manager** (`ats/auth`, `ats/jobs-db`, `ats/email`), read at runtime by the Lambda that needs them.
- Local inputs go in `infra/.secrets.local` (git-ignored). `infra/services/00-secrets.sh` copies them into Secrets Manager.
- JWT and service-token keys are random 256-bit values generated by the script, never typed by a person.
- `tests/security.test.mjs` (SEC-18) scans every tracked file and the git history for keys and passwords.
